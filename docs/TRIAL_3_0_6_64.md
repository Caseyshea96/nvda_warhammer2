# Trial run 3 fixes 0.6.64 — November 1, 2026

Trial run 3 on the friend's PC (0.6.63, installed in place correctly) got from
New Campaign through Select Lord to starting a campaign as Lord Mazdamundi.
Feedback (with his `speechhistory.txt` and `native-ui-graphics-preview.log`):

1. Mortal Empires said "Not supported yet."
2. Campaign difficulty is a combo box that could not be changed.
3. Lords were hard to pick: everything was one list ("1 of 50").
4. The choice should be sequential, like a decision tree, not one list.

Owner, during the work: announce cutscenes and how to skip them (Escape);
battles will be auto resolved for now (manual battles out of scope; recorded,
not built yet); remove the old screen-reader support and names (0.6.65, separate change).

## Changes

- **Select Lord as steps** (`lord_build_view` and friends in
  `diagnostics/graphics_preview.lua`), a view over the same complete read; every
  click still goes through the checked path of 0.6.62:
  1. "Select Lord. Choose a race. High Elves, 3 lords, 1 of 6". The game's lord
     list has no race names, only blank `race_spacer` entries between races, so
     groups come from the spacers and are named from a table of lord names
     (`lord_races`; a group with no known lord is "Other lords"). Enter opens
     a race.
  2. "High Elves. Tyrion, radio button, checked, 1 of 4" (+ Back). Enter
     chooses the lord; the setup is read by itself once the game shows the
     choice (a read on the key timer five ticks later, cancelled by any key).
  3. "Teclis is now selected. Campaign setup. Lord: Teclis, High Elves, Order
     of Loremasters, button, 1 of 5": Lord (Enter: choose again), Campaign
     difficulty and Battle difficulty combo boxes, the intro check box (only
     for lords that offer it), "Lord and faction details" (everything else on
     the screen, + Back), Start Campaign (asks first).
  - Backspace (new companion key, frontend only) goes back a step; on the
    first step it says "This is the first step. Escape returns to Select
    Campaign." Escape stays the game's.
  - `lord-list-flat.flag` in the app folder restores the single list.
- **Difficulty lists**: Enter on a combo box clicks it (path re-checked by ID),
  the game's list opens inside the combo box (`popup_menu`/`popup_list`,
  options are the text items), and it is read: "Campaign difficulty, list.
  Normal, selected, 2 of 6". Enter clicks the option ("Campaign difficulty,
  combo box, Hard"); Backspace clicks the combo box again to close it.
  Campaign has five options, Battle four (no Legendary), as the game shows.
- **Mortal Empires**: the campaign radio buttons (`button_campaign_entry`) are
  allowed targets with the same identity checks as Continue: "Mortal Empires
  selected."; the checked one says "... is already selected."
- **Intro movies**: at script load during the splash (only at game start:
  `os.clock()` under 90 s; about 25 s live) "Intro movies playing. Press Escape
  to skip them." Start Campaign now says "Starting the campaign. An intro movie
  plays first; press Escape to skip it." (was "The campaign map cannot be read
  yet", out of date since the campaign reader).
- **Menu key timer: one repeating timer** (`start_keys`). Live, the reader went
  silent for good right after a difficulty list opened (game running, no more
  ticks). The menu timer still registered its next single shot inside its own
  callback, the cause of the 0.6.58 campaign freeze. Now `register_repeating`
  once (logged "repeating timer"), single shots only as a fallback.
- **Select Campaign after Select Lord**: back from Select Lord a hidden
  `tooltip_campaign_select_lord` root layer replaces `Tooltip`; the screen
  check accepted only `Tooltip`, so every arrow re-read the screen and stayed
  on item 1 (also on 0.6.63). Any hidden extra layer is now accepted; a shown
  one still counts as a change.
- **Log restarts at 2 MiB** instead of becoming "unavailable": those re-reads
  filled the log and every activation then said "Accessibility log
  unavailable. Restart the game."
- Player guide: Select Lord steps, Backspace, difficulty lists, Mortal
  Empires, the movie notices.

Harness: 410 frontend scenarios (+ steps on the live fixture: races, lords,
setup, details, back, already-selected lord, Start Campaign prompt, difficulty
list open/choose/close, changed option refused, key before the delayed read,
unknown race; Mortal Empires press/one press/already selected/changed label;
Select Campaign with the lord tooltip layer; repeating timer registered once;
log restart; movie notice at start and not later). Older Select Lord tests run
with the flat-list flag.

## 0.6.65: NVDA only, new names

Owner request: purge every mention of the old screen reader ("Everything":
remove its support and the old pilot files, rename, migrate).

- Removed: the old screen reader's speech API and the companion's global
  hotkey / mouse-pointer mode (`Native.cs`, `HotkeyPolicy.cs`, hover speech),
  the original co-op pilot (`mod/`, `packaging/windows/`, its build, probe and
  packaging scripts, harnesses and docs), the interactive 0.5.2 build made from
  that source and the 0.4.3 diagnostic package mode. The NVDA scanner
  comparison stays (renamed); `diagnostics/native_ui_diagnostic.lua` is the
  proven baseline the runtime's traversal and logger are checked against.
- Renamed: pack `warhammer_access.pack` (scripts `warhammer_access.lua`,
  `warhammer_access_campaign.lua`), app folder `%LOCALAPPDATA%\WarhammerAccess`,
  fallback bridge `warhammer_access.jsonl`, C# namespace
  `WarhammerAccessibility`, skip-intro pack `warhammer_skip_intro.pack`.
  `-NoHotkeys` and `-ScreenReader Nvda` are still accepted (ignored) so older
  shortcuts and scripts start the companion.
- Migration (`Install.ps1`): an install under the old names is moved over
  after the new one is complete: the old pack is removed only if it matches the
  old receipt (same game folder), old App files only if they match the old
  manifest (others stay), option flags (`*.flag`) are copied, the old logs
  stay. A changed or unconfirmed old pack refuses the install. The desktop
  shortcut (same name) points to the new folder. TW Mod Manager users tick
  `warhammer_access` instead.
- `Start-Session -Direct` writes its own mod list (no longer reads TW Mod
  Manager's); `Install-Build` backs up the old-named install for this one
  upgrade.
- README and IMPLEMENTATION_PLAN rewritten to the current state; the old
  screen reader's review, pilot release, probe and co-op plan docs removed;
  other docs reworded. The repository folder and GitHub name still contain
  the old name: the owner renames those.

Checks: 410 frontend + 53 campaign scenarios, installer fixtures (+ move from
the old names: changed old pack refused, receipt for another folder refused,
hand-copied old pack refused, pack and recorded files removed, unrecorded
files and logs kept, flags copied), bridge, speech batch, add-on, scanner and
diagnostic checks. The ZIP holds the old names only in Install.ps1's migration
block.

Live: `Install-Build -Version 0.6.65 -Upgrade` over this PC's 0.6.64 (old
names): "Upgraded from version 0.6.64 to 0.6.65."; old pack, App folder and
receipt gone, new pack installed, shortcut retargeted.

## 0.6.66: Load Game, details in document order

- **Load Campaign** opens Load Game (main-menu target `button_load_campaign`,
  same checks as New Campaign). The Load Game panel (`load_save_game`) is
  read by the same bounded reader as Select Lord, as two steps:
  1. "Load Game. Choose a campaign. Eataine, The Eye of the Vortex,
     10/29/2026 5:07:07 PM, turn 1, list item, selected, 1 of 2"
     (`playthroughN` rows). Enter opens its saves (clicking the row first
     when it is not selected; the saves are then read by themselves).
  2. Save rows (`save_game`: name, difficulty, turn, date), "Load, button",
     "Enable all saves, check box" (read only: a game setting), Back. A save
     the game refuses says "unavailable" with the game's reason; Enter on it
     repeats the reason. Enter on a loadable save selects it and moves to
     Load; Load is one press ("Loading the save. This takes a minute."). The
     delete button is never offered. Backspace goes back a step.
  Fixture `tests/fixtures/load_game_live.lua` is the live capture.
- **Saves and the 0.6.65 rename**: saves record the mods they were made with.
  Load Game refuses saves made before 0.6.65: "You are missing the following
  mods: ..." (the old pack names). Continue Campaign still loads them (seen
  live: the trial-era autosave loaded and the renamed campaign reader read
  "Campaign map, 45 items."). Saves made from 0.6.65 on need
  `warhammer_access.pack`. Ticking "Enable all saves" in the game would also
  allow them (left to the player; it is a game setting).
- Select Lord details read like a document: race attributes with their text,
  faction and lord effects, starting units ("Starting unit: Flying
  Monster"), recommended campaign, then the rest.
- The developer automation timer is a repeating timer too.

Harness 415 frontend scenarios (+ Load Game steps, invalid save, unavailable
Load, setting not changed, campaign switch, loadable save → Load, replaced
Load button refused; details order; automation timer registered once).
